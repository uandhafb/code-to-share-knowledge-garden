## About this meetup

In this first meetup, we made music and visuals with code using two web-based languages: **Strudel** (sound) and **Hydra** (visuals).

## What is live coding?

Live coding is the practice of creating sound, visuals, or web choreography by writing and changing code in real time, with the code on screen for everyone to see.

In 2000, Adrian Ward and Alex McLean presented the **Generative Manifesto**. In 2004, the **TOPLAP** community drafted its own manifesto, with a clear request to performers: “Show us your screens.”

Links: [Live Coding: A User's Manual](https://livecodingbook.toplap.org/) · [TOPLAP](https://blog.toplap.org/)

## Strudel

[Strudel REPL](https://strudel.cc/) **[2022 · sound]**: an official port of the TidalCycles pattern language to JavaScript. Free, web-based, and open source. REPL stands for *read–eval–print loop*: an interactive place to write and evaluate code.

[TidalCycles ↗](https://tidalcycles.org/docs/) **[c. 2009 · sound]**: a live coding environment for algorithmic patterns, written in Haskell. Free and open source, it inspired Strudel and other related languages.

[Uzulangs](https://uzu.lurk.org/t/uzulangs/5660): a family of pattern-based live coding languages that includes TidalCycles and Strudel. **Mini-notation** is compact shorthand for describing patterns, which we can then transform with functions.

### Mini-notation

Paste this into the [Strudel REPL](https://strudel.cc/) and evaluate it:

```javascript
s("bd sd [~ bd] sd, hh*8")
```

`s(...)` selects sounds. The text inside the quotes is mini-notation:

| Code | What it does |
|---|---|
| `bd`, `sd`, `hh` | Select a bass drum, snare drum, and hi-hat. |
| Spaces | Divide the cycle into equal steps. |
| `[~ bd]` | Split one step into a rest, then a bass drum. |
| `~` | Leave a rest. |
| `,` | Layer patterns so they play together. |
| `hh*8` | Play eight hi-hats per cycle. |

At the default tempo of 0.5 cycles per second, one cycle lasts two seconds. Strudel handles the timing and repeats the pattern.

### Transform the pattern

The quoted mini-notation describes the starting pattern. The functions below it transform that pattern and control its sound. Try this example on its own in the REPL:

```javascript
$: s("bd cp [~ bd] cp, lt?")
  .chunk(3, x => x.ply(2))
  .gain(sine.range(0.1, 0.4).slow(3))
  .pan(rand)
```

- **`$:`** starts a pattern in the Strudel REPL.
- **`cp`** selects a clap; **`lt?`** selects a low tom with a 50% chance of being left out.
- **`.chunk(3, x => x.ply(2))`** divides the pattern into three parts and repeats each event twice in one selected part. The selected part advances each cycle.
- **`.gain(sine.range(0.1, 0.4).slow(3))`** varies the volume smoothly between 0.1 and 0.4 over three cycles.
- **`.pan(rand)`** gives events random positions between the left and right channels.

### The same mini-notation

Install the libraries in your Python environment:

```bash
python3 -m pip install numpy sounddevice
```

```python
import numpy as np
import sounddevice as sd

SR = 44100  # samples per second
CYCLE = 2.0  # one cycle = two seconds

def bd():
    t = np.linspace(0, 0.3, int(SR * 0.3), endpoint=False)
    freq = 120 * np.exp(-t * 20) + 40
    phase = 2 * np.pi * np.cumsum(freq) / SR
    return np.sin(phase) * np.exp(-t * 12)

def snare():
    t = np.linspace(0, 0.2, int(SR * 0.2), endpoint=False)
    noise = np.random.uniform(-1, 1, len(t))
    return noise * np.exp(-t * 25) * 0.6

def hh():
    t = np.linspace(0, 0.05, int(SR * 0.05), endpoint=False)
    noise = np.diff(np.random.uniform(-1, 1, len(t)), prepend=0)
    return noise * np.exp(-t * 80) * 0.3

events = [(0.0, bd), (0.5, snare), (1.25, bd), (1.5, snare)]
events += [(i * 0.25, hh) for i in range(8)]

buffer = np.zeros(int(SR * CYCLE))
for onset, make_sound in events:
    hit = make_sound()
    start = int(onset * SR)
    end = min(len(buffer), start + len(hit))
    buffer[start:end] += hit[:end - start]
buffer /= np.max(np.abs(buffer))

try:
    sd.play(buffer, SR, loop=True)
    input("Playing... press Enter to stop")
finally:
    sd.stop()
```

In this Python example, we:

- Synthesize each drum sound.
- Set the hit times in seconds: `0`, `0.5`, `1.25`, `1.5`, and so on.
- Place and mix the hits in an audio buffer.
- Play the buffer on a loop.

In Python, we program the clock. In Strudel, we describe the rhythm, and Strudel handles the clock for us, leaving us free to describe and transform the pattern.

### The REPL and the shortcuts

In Strudel, the P in REPL can also stand for *play*: change the code and hear the change right away, without stopping the music.

> write → evaluate → listen → change → evaluate → listen…

| Action | Mac | Windows and Linux |
|---|---|---|
| Play or update | Control (⌃) + Enter | Ctrl + Enter |
| Stop | Control (⌃) + . | Ctrl + . |
| Comment or uncomment | Command (⌘) + / | Ctrl + / |

On a Mac, play and stop use **Control**, not Command.

### Time: cycles, not beats

Scores and DAWs count beats in **BPM** (beats per minute). Strudel counts **cycles**: **CPS** (cycles per second) or **CPM** (cycles per minute).

| Code | What it means |
|---|---|
| `setcps(0.5)` | The default: one cycle every two seconds. |
| `setcps(1)` | One cycle every second. |
| `setcpm(30)` | 30 cycles per minute, the same as `setcps(0.5)`. |
| `setcpm(1)` | One cycle every 60 seconds. |
| `setcps(120/60/4)` | 120 BPM with four beats per cycle: the same as `setcps(0.5)` and `setcpm(30)`. |

To convert, divide the BPM by the number of beats per cycle: CPM = BPM ÷ beats per cycle.

Each pattern fills exactly one cycle. More sounds make it denser, not longer. At the default tempo:

| Pattern | Steps | Each step lasts |
|---|---|---|
| `s("bd sd bd sd")` | 4 | 0.5 seconds |
| `s("bd sd cp cp rim casio")` | 6 | about 0.33 seconds |
| `s("bd [sd sd] cp hh")` | 4 | 0.5 seconds; each `sd` inside the brackets lasts 0.25 seconds |

### Sounds

`sound("...")` and `s("...")` do the same thing. Open the **sounds** tab in the Strudel REPL to see and hear them all.

| Name | Sound | How many |
|---|---|---|
| `bd` | bass drum (kick) | depends on the bank |
| `sd` | snare drum | depends on the bank |
| `hh` / `oh` | closed / open hi-hat | depends on the bank |
| `cp` | clap | depends on the bank |
| `rim` | rimshot | depends on the bank |
| `lt` / `mt` | low / mid tom | depends on the bank |
| `insect` | insects | 3 (`insect:0` to `insect:2`) |
| `wind` | wind | 10 (`wind:0` to `wind:9`) |
| `jazz` | jazz drum hits | 8 (`jazz:0` to `jazz:7`) |
| `metal` | metal hits | 10 (`metal:0` to `metal:9`) |
| `east` | percussion | 9 (`east:0` to `east:8`) |
| `crow` | crows | 4 (`crow:0` to `crow:3`) |
| `casio` | a small Casio keyboard | 3 (`casio:0` to `casio:2`) |
| `space` | space sounds | 18 (`space:0` to `space:17`) |
| `numbers` | a voice saying numbers | 9 (`numbers:0` to `numbers:8`) |

Set the tempo first; without `setcps`, the tempo stays at the default of 0.5. Evaluate one pattern line at a time:

```javascript
setcps(0.7) // 0.7 cycles per second: one cycle about every 1.4 seconds
s("bd sd") // two events per cycle
s("bd sd hh cp")
s("insect wind crow space")
```

**Sample numbers** pick a different recording of the same sound. Counting starts at 0, not 1:

```javascript
s("jazz:0 jazz:1 jazz:2 jazz:3")
n("0 1 2 3").s("jazz") // the same thing, written with n
s("numbers:1 numbers:2 numbers:3")
```

Watch the spaces: `jazz:3` is sample 3 of `jazz`, but `jazz 3` is **two** steps: `jazz`, then a sound called `3`, which doesn't exist.

**Banks** use the same names with sounds from classic drum machines. Some banks don't have every sound:

```javascript
s("bd sd hh cp").bank("RolandTR909")
s("bd sd hh cp").bank("RolandTR808")
s("bd sd hh cp").bank("LinnDrum")
```

### Mini-notation symbols

| Symbol | Name | Example | What you hear |
|---|---|---|---|
| space | sequence | `"bd sd cp"` | three steps in one cycle |
| `~` | rest | `"bd ~ sd ~"` | silence on steps 2 and 4 |
| `[ ]` | nest | `"bd [sd sd]"` | step 2 split in two |
| `< >` | one per cycle | `"bd <sd cp>"` | `sd`, then `cp`, then `sd`… |
| `*` | faster | `"bd hh*4"` | four hi-hats inside one step |
| `/` | slower | `"bd sd/2"` | `sd` only every other cycle |
| `!` | replicate | `"bd!3 sd"` | the same as `"bd bd bd sd"` |
| `@` | longer | `"bd@3 sd"` | `bd` takes 3/4 of the cycle |
| `?` | maybe | `"hh*8?"` | each hi-hat has a 50% chance |
| `\|` | random pick | `"bd [sd\|cp\|rim]"` | a new pick every cycle |
| `,` | layers | `"bd sd, hh*4"` | both play at the same time |
| `.` | groups | `"bd sd . hh hh hh"` | the same as `"[bd sd] [hh hh hh]"` |

**Sequence:** spaces divide the cycle into equal steps.

```javascript
s("bd sd cp cp") // 4 steps
s("bd sd cp cp rim casio") // 6 steps: denser, same cycle
```

**Rest** with `~`, **nest** a step inside a step with `[ ]`, and play **one per cycle** with `< >`:

```javascript
s("bd ~ sd ~")
s("bd [sd sd] cp hh")
s("jazz [rim [jazz casio]] ~ casio") // nests can go deeper
s("bd <sd cp rim>")
```

**Faster** with `*` and **slower** with `/`:

```javascript
s("bd hh*4")
s("bd [hh hh hh hh]") // the same: * repeats an event n times inside its step
s("lt sd/4") // / slows an event down: sd plays only once every 4 cycles
s("[lt sd/4]*4") // the whole pattern 4 times per cycle, so sd plays once per cycle
```

**Replicate** with `!` and make an event **longer** with `@`:

```javascript
s("bd!3 sd") // ! repeats the event 3 times, each as its own step (4 steps)
s("bd bd bd sd") // the same thing, written out
s("bd@4 sd") // @ makes bd 4 times longer than sd: bd gets 4/5 of the cycle, sd 1/5
```

**Maybe** with `?`: each sound gets a chance to be **skipped**. The number after `?` is the chance to skip, so `?` alone is 50%, `?0.2` skips 20% of the sounds, and `?0.8` skips 80%.

```javascript
s("hh*8?")
s("hh*8?0.2")
s("hh*8?0.8")
```

**Random pick** with `|`: every cycle, Strudel picks one of the options at random, and every option has the same chance (50% each for two options, about 33% each for three, 25% each for four).

```javascript
s("bd [sd|cp|rim]") // the second step: sd, cp, or rim, about 33% each
s("bd sd | cp ~ cp?") // the whole cycle: "bd sd" or "cp ~ cp?", 50% each
```

**Layers** with `,` play several patterns at the same time, and **groups** with `.` save typing brackets:

```javascript
s("bd, sd, hh*4")
s("bd sd, hh*4, ~ cp")
s("bd sd . ~ cp?0.8 lt*2")
s("[bd sd] [~ cp?0.8 lt*2]") // the same thing, with brackets
```

#### Polyrhythm `[ ]` vs. polymeter `{ }`

With **square brackets**, each layer is squeezed into one cycle, so the steps have different lengths. Here, three steps play against two, and every cycle sounds the same:

```javascript
s("[jazz casio rim, hh lt]")
```

```text
|      jazz       |      casio      |       rim       |
|            hh            |            lt            |
```

With **curly brackets**, every step has the same length. The first layer sets the step size, and the other layers keep looping at their own length, so they drift. Here, there are two steps per cycle, so `lt bd sd` needs three cycles to come back around. Every cycle is different, and cycle 4 starts again like cycle 1:

```javascript
s("{hh cp, lt bd sd}")
```

```text
 cycle 1      cycle 2      cycle 3
| hh | cp |  | hh | cp |  | hh | cp |
| lt | bd |  | sd | lt |  | bd | sd |
```

### Functions: adding a little spice

The mini-notation inside the quotes is the pattern. The functions after the dot change what we do with it.

| Function | What it does |
|---|---|
| `.fast(n)` | plays the pattern *n* times as fast |
| `.slow(n)` | plays the pattern *n* times as slow |
| `.rev()` | plays it backwards |
| `.jux(rev)` | normal in the left ear, backwards in the right |
| `.ply(n)` | repeats every sound *n* times |
| `.degradeBy(0.5)` | removes 50% of the sounds at random |

```javascript
s("bd sd [~ bd] sd").fast(2)
s("bd sd [~ bd] sd").slow(2)
s("bd sd cp hh").rev()
s("bd sd cp hh").jux(rev)
s("bd sd").ply("<1 2 3>")
s("hh*8").degradeBy(0.5)
```

### Effects: change the sound

| Effect | What it does | Values |
|---|---|---|
| `.gain()` | volume | 0 is silent, 0.8 is the default, 1 is louder |
| `.room()` | reverb, like a big room | 0 to 1 |
| `.delay()` | echo | 0 to 1 |
| `.speed()` | playback speed (and pitch) | 2 is higher, −1 is backwards |
| `.pan()` | left / right position | 0 is left, 0.5 is the middle, 1 is right |

**Gain**, including a slider you can move with the mouse:

```javascript
s("hh*16").gain("0.55")
s("hh*16").gain("[.25 1]*4")
s("bd sd, hh*8").gain(slider(0, 0, 1))
```

**Room**, **delay**, and **speed** (negative speeds play backwards):

```javascript
s("bd rim? bd*4 cp?0.8").room(0.5)
s("bd rim bd cp").delay("0.5")
s("bd rim bd cp").speed("<1 2 -1 -2>")
```

**Pan**: use headphones or two speakers.

```javascript
s("bd rim bd cp").pan("0 1")
s("hh*16").pan(sine) // swings left and right
s("hh*16").pan(rand) // every sound lands in a random place
```

All together:

```javascript
s("bd sd [~ bd] <sd cp>, hh*8?").bank("RolandTR909").room(0.2).jux(rev)
```

### More than one pattern: `$:` and `stack()`

| | `$:` (one per line) | `stack()` (one pattern) |
|---|---|---|
| How | Each line is an independent pattern. | The layers are tied together; functions after `stack()` change every layer. |
| Mute | `_$:` mutes just that line. | Comment out a layer with `//`. |

```javascript
$: s("bd sd [~ bd] sd")
_$: s("hh*8").gain(0.5)
$: s("~ cp")
```

```javascript
stack(
  s("bd sd [~ bd] sd"),
  // s("lt*8")
).pan("<0 0 1 0>").gain(0.5)
```

## Hydra

- A browser-based live coding environment for real-time video synthesis.
- Created by **Olivia Jack** in **2017**.
- Written in JavaScript.
- Runs entirely in the browser, with no installation needed.
- Inspired by **analog modular video synthesizers**: you patch sources through transformations into outputs.
- Free and open source.

Links: [Hydra editor](https://hydra.ojack.xyz) · [Documentation](https://hydra.ojack.xyz/docs/) · [Every function, live](https://hydra.ojack.xyz/api/) · [Hydra garden](https://hydra.ojack.xyz/garden/) (community projects and tutorials)

### How to run

| Shortcut | What it does |
|---|---|
| Ctrl + Enter | Runs the line you're on. |
| Alt + Enter | Runs a block (lines with no empty line between them). On a Mac, use Option + Enter. |
| Ctrl + Shift + Enter | Runs everything. |
| Ctrl + / | Comments or uncomments a line. |
| Ctrl + Shift + H | Hides or shows the code. |
| `hush()` | Clears the screen: type it and run it. |

The shortcuts are the same on Mac, Windows, and Linux; on a Mac, they use **Control**, not Command, and Alt is **Option**. In this garden, **Ctrl/⌘ + Enter** runs the code box you're typing in.

A first taste. Change a number, then press **Run**:

```hydra
noise(4).repeat(10, 10, 0.5, 0.5).pixelate(60, 30).colorama(-0.5).out()
```

### How Hydra code flows

Like a modular synth, every line of Hydra patches a signal from a source, through transformations, to an output:

1. [[category:hydra/source|Source]] and [[category:hydra/output|Output]]: a source generates the signal (`osc`, `noise`, `voronoi`, `shape`), and `.out()` sends it to an output.
2. Transformations: change the signal. [[category:hydra/geometry|Geometry]] and [[category:hydra/color|Color]] change the image; [[category:hydra/blend|Blend]] brings in a second image. (Modulate, which also uses a second image, is for next week.)
3. [[category:hydra/patterns|Patterns & signals]]: make any value change over time.

Read it like a recipe: left to right, one step after another.

```hydra
osc(20, 0.1, 1).kaleid(4).colorama(0.2).out()
```

Start with the [[category:hydra/source#rules-for-every-function|rules for every function]].
